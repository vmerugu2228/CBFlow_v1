## Answer to the ECO / POPT question

`flow(release,signoff_flows)` is used to sort releases into two groups:
- **signoff**: releases the exit it verified, and is attached to that exit (`attach_to`).
- **implementation**: any one of these releases the exit.

ECO and POPT are implementation:
- They release netlist / def / gds.
- ECO tags are `<EXIT>_ECO<n>`.
- The tag audit already hardcodes ECO as implementation.

So they should leave the list.

The signoff set the configs actually support today is the flows with `release,exit_from`: STA, PV, LEC (PD) and GLS_FUNC, GLS_SCAN_MBIST (DFT). CLP and EMIR are signoff by intent but have no `exit_from`-based handler yet.

The DV, RTL, SCAN_INSERT and ATPG flows are a third kind: each owns its exit. They need release tags, exit orders and per-discipline phase plans (#2a, #2b, #5), not membership in `signoff_flows`.

1. **RTL top metrics:** I couldn't find the metric names RTL flows publish to SmartGrid. The fix for #7 needs those names.
2. **Stage-table categories:** I didn't check whether DFT / DV / RTL stage metrics use categories outside `flow(dashboard,stage_tables)` (`{design timing clock} {routing} {power}`), which would hide their stage tables.
3. **CLP / EMIR:** I kept them in `signoff_flows`, but did not check whether their Synopsys / Cadence release handlers attach to an exit.
4. **Exit orders:** The order inside RTL (LINT / CDC / UPF are parallel) and DFT (ATPG_POSTPD_EXIT depends on PD BTO) can't be expressed as a single list. The proposed lists are a starting point.

6. **`cli(discipline,…)` values:** I didn't check whether it accepts a non-discipline owner (for moving the checklist to global).
7. **DFT_INSERT_PASS1 RTL input:** I didn't check whether it takes a filelist or a file, so I proposed no handshake for it.
8. **Line numbers:** `run_cmd.py`, `releases.py`, `release_utils.tcl` and `candidate_cmd.py` are being edited in the working tree right now, so their line numbers may shift.
