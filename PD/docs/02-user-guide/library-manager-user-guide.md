# CBflow Library Manager User Guide

## Overview

The Library Manager discovers, organizes and validates the libraries a project uses (NDM, DB, LEF, Liberty,
GDS, CDL, Verilog, hierarchical blocks) across tracks, VT flavors and PVT corners. Libraries are delivered as
**library tags**:

```
<lib_tag_root>/<tech>/<TAG>/
    lib_config.tcl        generated, pure data (sourced by the config cascade)
    blocks_config.tcl     generated by `add --category block` (sourced from lib_config.tcl)
    stdcell/ memory/ io/ ip/ analog/ block/<b>/   symlinked views
    MANIFEST.tcl  logs/
```

- `lib_tag_root` resolves as: `--lib-tag-root` flag > `CBFLOW_LIB_TAG_ROOT` > `project(lib_tag_root)` (PD overlay
  `<proj>_pd_config.tcl`) > `tech(lib_tag_root)`. It **must be outside `CBFLOW_ROOT`** — a root inside the
  framework tree is rejected, not skipped.
- A run picks its tag with `project(lib_config_tag)` (PD overlay default; a user_config value wins).

The commands are PD-owned and auto-dispatched: `cbflow flow library-manager <sub>` (or `PD/bin/cbflow-pd flow
library-manager <sub>`).

| Subcommand | Purpose |
|------------|---------|
| `generate` | Build a tag's `lib_config.tcl` from library directories |
| `add` | Add one category (stdcell / memory / io / ip / analog / block) to an existing tag |
| `check` | Validate a tag: referenced paths, required views per category, a design's cells vs the tag |
| `status` | Signoff-readiness: VTs, LEF-tech / RCX / timing coverage, dont_use masks |
| `coverage` | Track x corner matrix |
| `list` | Configured library sets (filter by corner / voltage / temperature) |
| `scan` / `verify` | Discover `.lib` files / read their headers |
| `generate-mmmc` | Analysis views from a library directory |

## Quick Start

```bash
# Open-source (sky130, project opensky): check and introspect tag OSS2
cbflow flow library-manager check  --tech skywater_130nm --lib_tag OSS2
cbflow flow library-manager status --tech skywater_130nm --project opensky --lib_tag OSS2

# Commercial (gf_22nm): build a tag from the vendor library root
cbflow flow library-manager generate --tech gf_22nm --lib-root /libs/gf_22nm --tag P0
cbflow flow library-manager coverage --tech gf_22nm --tag P0
```

## generate — build a tag

Scans library directories, discovers libraries by track / VT / corner and writes
`<lib_tag_root>/<tech>/<TAG>/lib_config.tcl` with fully resolved paths.

```bash
cbflow flow library-manager generate --tech gf_22nm --lib-root /libs/gf_22nm --tag P0
cbflow flow library-manager generate --tech skywater_130nm --tag OSS0 \
    --lib-root ~/eda/pdks/sky130A/libs.ref/sky130_fd_sc_hd
```

**What it does:**
1. Reads `tech(tracks_available)` and `tech(vt_variants_available)` from the tech config
2. Scans NDM, LEF, DB and Liberty files; extracts track, VT and corner from file names
3. Cross-checks PVT against `.lib` headers (`nom_voltage`, `nom_temperature`)
4. Writes `lib_config.tcl` — pure data, no variables or loops
5. Reports missing memory / IO corners and PVT mismatches

| Option | Description | Example |
|--------|-------------|---------|
| `--lib-root` | Library root (default: `tech(lib_root)`) | `/libs/gf_22nm` |
| `--tech` / `--tech-config` | Technology name, or an explicit `tech_config.tcl` | `gf_22nm` |
| `--tag` | Tag name; output `<lib_tag_root>/<tech>/<TAG>/lib_config.tcl` | `--tag P0` |
| `--lib-tag-root` | Override the tag root | `/proj/eda/lib_tags` |
| `--stdcell-path` | Additional stdcell roots | `--stdcell-path /libs/eco /libs/channel` |
| `--memory-path` / `--io-path` | Override memory / IO directories | `--memory-path /libs/sram_v2` |
| `--analog-path` / `--ip-path` | Analog / IP macro directories (first-class categories) | `--ip-path /libs/pll` |
| `--exclude` | Glob patterns on the full path | `--exclude "*ulvt*" "*/eco/*"` |
| `--tracks` / `--vts` | Override auto-detection | `--tracks "9T 7.5T"` |
| `--incremental` | Keep entries not found in this scan | |
| `--allow-missing` | Proceed when declared source paths are missing (bootstrapping) | |
| `--output` | Dev escape hatch: write one flat `lib_config.tcl` at this path | |

## add — extend a tag by one category

```bash
cbflow flow library-manager add --tech <tech> [--project <p>] --tag <TAG> --category <cat> --path <dir> [<dir>...]
```

| Option | Description |
|--------|-------------|
| `--tag` | Existing tag to extend (required) |
| `--category` | `analog`, `ip`, `memory`, `io`, `stdcell` or `block` (required) |
| `--path` | Source directories (for `block`: the block's PNR release dir) |
| `--tech` / `--tech-config` | Technology name, or an explicit `tech_config.tcl` |
| `--tracks`, `--vts` | `stdcell` only; auto-detected if omitted |
| `--exclude` | Glob patterns to skip |
| `--allow-missing` | Proceed if source paths are missing |
| `--pv-pending` | `block` only, see below |
| `--lib-tag-root` | Override the tag root (same precedence as `generate`) |
| `--project` | Project whose `project(lib_tag_root)` locates the tag (default `$CBFLOW_PROJECT_NAME`) |
| `--version` | Config version (default `v1.0.0`) |

Other categories are preserved. When a non-stdcell category is added, the existing `tech(corners)` list is kept.

### Shared categories (memory, io, ip, analog)

Every view is bundled: files are symlinked into `<tag>/<cat>/{lef,gds,cdl,verilog,lib,...}` and
`lib_config.tcl` gets:

```bash
cbflow flow library-manager add --tech skywater_130nm --project opensky --tag OSS2 \
    --category memory --path ~/eda/pdks/sky130A/libs.ref/sky130_sram_macros
```

```tcl
set tech(lef,memory)     [list .../sky130_sram_1kbyte_1rw1r_32x256_8.lef]
set tech(gds,memory)     [list .../sky130_sram_1kbyte_1rw1r_32x256_8.gds]
set tech(cdl,memory)     [list .../sky130_sram_1kbyte_1rw1r_32x256_8.spice]   ;# .cdl / .spice / .sp
set tech(verilog,memory) [list .../sky130_sram_1kbyte_1rw1r_32x256_8.v]
set tech(lib,<corner>,timing,memory) [list ...]
```

Empty categories are written as `[list ]`. A memory characterized at fewer corners than the MMMC library sets
use is mapped with `tech(memory,lib_set_map)` (reported as a substituted corner by `check`).

### Blocks (`--category block`)

Adds a released hierarchical block (DL3 or DL2) as a hard macro for its parent. `--path` is the block's PNR exit
release `<release,path>/<phase>/<block>/PNR/<exit>`:

```bash
cbflow flow library-manager add --tech skywater_130nm --project opensky --tag OSS1 \
    --category block --path <release,path>/P1/mac_array/PNR/PRO_EXIT
```

| View | From |
|---|---|
| `lef/<b>.lef`, `netlist/<b>.v`, `netlist/<b>.lvs.v` (opt), `def/<b>.def` (opt), `sdc/<b>.sdc` (opt), `lib/<b>__<lib_set>.lib` | PNR release (`--path`) |
| `gds/<b>.gds`, `netlist/<b>.cdl` | Sibling **PV** release `<phase>/<block>/PV/<exit>`, which must be `RELEASE_COMPLETE` with `STATUS=PASS` |
| `spef/<b>_<rc>.spef` | PNR release `spef/` (symlinked, one per RC corner; none before `pro`) |

`--pv-pending` takes GDS / CDL from the PNR release while PV has not released yet, and records
`tech(block,<b>,pv_release) "PENDING"`. Re-run `add` without the flag once PV releases. Without the flag there is
no fallback: a missing or failed PV release is an error.

`add` regenerates `<tag>/blocks_config.tcl` on every run (do not edit it):

```tcl
set tech(blocks) [list gcd mac_array]
set tech(block,mac_array,release)       ".../P1/mac_array/PNR/PRO_EXIT"
set tech(block,mac_array,pv_release)    ".../P1/mac_array/PV/PRO_EXIT"   ;# or "PENDING"
set tech(block,mac_array,lef)           "$_lib_tag_dir/block/mac_array/lef/mac_array.lef"
set tech(block,mac_array,lib_sets)      [list ff_1p95v_100c ff_1p95v_m40c ss_1p60v_100c ss_1p60v_m40c]
set tech(block,mac_array,lib,ss_1p60v_100c) "$_lib_tag_dir/block/mac_array/lib/mac_array__ss_1p60v_100c.lib"
set tech(block,mac_array,spef_corners)  [list rc_max rc_min rc_typ]
set tech(block,mac_array,spef,rc_max)   "$_lib_tag_dir/block/mac_array/spef/mac_array_rc_max.spef"
```

Flat STA (`sta(oss,sta,mode) flat`) reads `tech(block,<b>,netlist)` and `tech(block,<b>,spef,<rc>)` for every
descendant. A parent whose child is missing from the tag fails with the `add` command to run.

## check — validate a tag

```bash
cbflow flow library-manager check --tech <tech> --lib_tag <TAG> [--project <p>] [--verbose]
```

`--lib_tag` (also `--lib-tag`, `--tag`) is found under the projects' `lib_tag_root`; `--project` is only needed
when several projects hold the tag. Without `--lib_tag`, `check` validates the library paths the tech config
references (`check --verbose` lists each).

With a tag it prints:

1. **Path validation** — every library reference of the tag exists.
2. **Required views** — one row per library, one column per view. The views each category must have come from
   `tech(required_views,<category>)` in the tech config, e.g. for skywater_130nm:

   ```tcl
   set tech(required_views,stdcell) {lef lib gds cdl verilog}
   set tech(required_views,memory)  {lef gds cdl verilog lib}
   set tech(required_views,block)   {lef gds netlist lvs_netlist cdl def sdc lib spef}
   ```

   `lib` is checked per corner of the project's MMMC library sets, `spef` per MMMC RC corner. Stdcell rows are
   track x VT; memory / io / ip / analog rows are each macro; block rows are each hard block.

Real output (`check --tech skywater_130nm --lib_tag OSS2`):

```
  Required views — library tag OSS2  (tech(required_views,<category>))
    lib corners  : ff_1p95v_100c ff_1p95v_m40c ss_1p60v_100c ss_1p60v_m40c  (project opensky MMMC library sets)
    spef corners : rc_max rc_min rc_typ
    OK = present · † = from the tech config (PDK) · n/m = corners covered · * = substituted corner · MISSING · — = no library
+----------+-----------------------------------+-----+------+-----+-----+---------+---------+-------------+-----+-----+---------+
| category |              library              | lef | lib  | gds | cdl | verilog | netlist | lvs_netlist | def | sdc |   spef  |
```

Legend:

| Mark | Meaning |
|------|---------|
| `OK` | present in the tag |
| `OK†` | not in the tag, taken from the tech config (the PDK), e.g. `tech(<track>,gds_stdcell)` |
| `n/m` | corners covered out of the corners required (`lib`, `spef`) |
| `*` | a substituted corner (`tech(memory,lib_set_map)`) |
| `MISSING` | required and absent — fails the check (exit 1) |
| `—` | no library of that category in the tag |

Blocks added before `pro` (e.g. from a PLACE_EXIT release) have no SPEF, so `spef` reports `MISSING`.

### A design's cells vs the tag

Add `--design <block>` with a release tag of that block to check every cell / module the design instantiates
(types it defines itself excluded) against the tag's views. Cells are matched by name in each view (lib cell,
LEF MACRO, CDL SUBCKT, Verilog module, GDS structure); physical-only cells (fillers, well taps, endcaps, decaps)
show `n/a`.

```bash
# the BTO netlist of gcd (P3) vs OSS2
cbflow flow library-manager check --tech skywater_130nm --lib_tag OSS2 \
    --project opensky --design gcd --netlist_tag BTO --phase P3

# macros / blocks the LINT_SIGNOFF RTL filelist instantiates (phase auto-detected when only one has the tag)
cbflow flow library-manager check --tech skywater_130nm --lib_tag OSS2 \
    --project opensky --design gcd --rtl_tag LINT_SIGNOFF
```

| Option | Meaning |
|--------|---------|
| `--design` | Block whose release the tags name |
| `--netlist_tag` / `--netlist-tag` | Release tag of the design netlist (`<release,path>/<phase>/<b>/<FLOW>/<tag>/netlist/<b>.v`) |
| `--rtl_tag` / `--rtl-tag` | Release tag of the RTL filelist (`.../RTL_LINT/<tag>/rtl/<b>.f`) |
| `--phase` | Release phase of those tags (default: the one phase that has them) |

Real output (netlist):

```
  gcd netlist BTO vs library tag OSS2: <release,path>/P3/gcd/PNR/BTO/netlist/gcd.v
    71 cell / module type(s) instantiated, 31471 instance(s) ...
+-----------------------------------+----------+-----------+-----+-----+-----+-----+---------+-...
|                cell               | category | instances | lef | lib | gds | cdl | verilog | ...
+===================================+==========+===========+=====+=====+=====+=====+=========+=...
|           70 cell types           | stdcell  |   31469   |  OK |  OK |  OK |  OK |    OK   | ...
| sky130_sram_1kbyte_1rw1r_32x256_8 |  memory  |     2     |  OK | 4/4 |  OK |  OK |    OK   | ...
+-----------------------------------+----------+-----------+-----+-----+-----+-----+---------+-...
  Cells with missing views: 0
```

Use it before a parent's PNR (are all children in the tag?) or before PV / LEC of a block (does the tag carry
GDS / CDL for every cell the netlist uses?).

## status — signoff readiness

```bash
cbflow flow library-manager status --tech skywater_130nm --project opensky --lib_tag OSS2
```

`--project` enables the project's VT flavors (`project(vt_flavors)`); omit it for a tech-wide view. Without
`--lib_tag` the first available tag (or `CBFLOW_LIB_CONFIG_TAG`) is used. Exit code 0 = ready, 1 = gaps.

```
  Library Manager Status — tech=skywater_130nm version=v1.0.0
  lib_config: <lib_tag_root>/skywater_130nm/OSS2/lib_config.tcl
  Project:    opensky  metal_stack=5M  vts=svt
  VT flavors
    Available in tech: svt
      ENABLED  svt    pattern=*
  LEF-tech coverage (metal_stack × track)
    5M    hd=OK
  RCX coverage (metal_stack × rc_corner × format)
    5M    rc_max     formats=openrcx,tlef              OK
    ...
  Timing/NDM coverage (track × VT — from lib_config.tcl)
    hd    svt    lib_nom=1 timing_corners=16
  Per-axis coverage summary:
    LEF-tech:      0 missing
    RCX:           0 missing
    Timing/NDM:    0 missing
  READY — all declared axes populated. Multi-VT setup complete.
```

A warning is printed when `lib_config.tcl` is older than `tech_config.tcl`.

## coverage, list, scan, verify

```bash
cbflow flow library-manager coverage --tech gf_22nm --tag P0          # track x corner matrix
cbflow flow library-manager list --tech gf_22nm --corner ss --voltage 0.80
cbflow flow library-manager scan --path /libs/gf_22nm --recursive --format json
cbflow flow library-manager verify --path /libs/gf_22nm --recursive --verbose
```

`coverage` locates a tag through the active project; outside a run shell set `CBFLOW_PROJECT_NAME`
(e.g. `CBFLOW_PROJECT_NAME=opensky cbflow flow library-manager coverage --tech skywater_130nm --tag OSS2`).

## Selecting a tag per run

```tcl
# PD/config/project/opensky/v1.0.0/opensky_pd_config.tcl — project default
set project(lib_tag_root)   "/proj/eda/lib_tags"
set project(lib_config_tag) "OSS0"

# workarea/<block>/uc_<FLOW>.tcl — per run (wins)
set project(lib_config_tag) "OSS2"
```

The workarea scripts set it from `LIB_TAG` (`LIB_TAG=OSS2 ./run_signoff.sh gcd PRO_EXIT`). A typical hierarchy keeps
one tag per refresh of the children: OSS0 (stdcells), OSS1 (+ P1 DL3 blocks), OSS2 (+ SRAM macros, later blocks).

## Generated lib_config.tcl

The output is **pure data** — every path fully resolved:

```tcl
# AUTO-GENERATED by: cbflow flow library-manager generate
set tech(9T,svt,ndm) [list "/libs/gf_22nm/Back_End/ndm/tcbn22cllbwp9tsvt.ndm"]
set tech(9T,ndm)     [list "/libs/.../tcbn22cllbwp9tsvt.ndm" "/libs/.../memory.ndm" ...]
set tech(9T,svt,lib,ss_0p76v_150c,timing) [list "/libs/.../tcbn22cllbwp9tsvtss0p76v150c_ccs.lib"]
set tech(9T,lib,ss_0p76v_150c,timing)     [list ... all VTs + memory + io ...]
set tech(corners) {ff_0p84v_m40c ss_0p76v_150c ss_0p76v_25c tt_0p80v_25c ...}
```

## Tags for different scenarios

```bash
cbflow flow library-manager generate --tech gf_22nm --tag full
cbflow flow library-manager generate --tech gf_22nm --tag svt_lvt --exclude "*ulvt*" "*hvt*"
cbflow flow library-manager generate --tech gf_22nm --tag P0 --incremental
```

## Exclude patterns

Exclude matches the **full absolute path**:

```bash
--exclude "*ulvt*"              # skip all ULVT libs
--exclude "*/eco/*"             # skip libs under eco/
--exclude "*channel*"           # skip channel cell libs
```

## PVT verification

`generate` checks each library twice: the corner / voltage / temperature from the file name, then the `.lib`
header (`nom_voltage`, `nom_temperature`). Mismatches are reported:

```
  PVT Verification (filename vs .lib header):
    Verified: 168  Skipped: 0
    MISMATCHES: 1
      tcbn22cllbwp9tsvtss0p76v25c_ccs.lib — temp: file=25C header=150C
```

## Filename conventions

| Component | Pattern in filename | Example |
|-----------|-------------------|---------|
| Track | `\d+p?\d*t` | `9t`, `7p5t`, `5t` |
| VT | `svt`, `lvt`, `ulvt`, `hvt` | `tcbn22cllbwp9t**svt**` |
| Corner | `(ss\|tt\|ff)(0p\d+v)(m?\d+c)` | `ss0p76v150c` |
| Format | `.ndm`, `.db`, `_ccs.lib`, `.lef` | `*_ccs.lib` |
