# Test Patterns: Types, Generation, and Optimization

## Overview of Test Patterns

Test patterns are the stimuli applied to a design to detect manufacturing defects. Each pattern specifies the values to be loaded into scan chains, the sequence of clock operations, and the expected responses at scan outputs. The quality, efficiency, and appropriateness of test patterns directly determine the effectiveness and cost of production testing.

Modern test strategies employ multiple pattern types, each targeting different fault classes and test objectives. Understanding the characteristics of each type is essential for building a comprehensive test program.

## Structural Test Patterns

Structural patterns are generated by ATPG tools based on the gate-level netlist and fault models. They do not require knowledge of the design's function -- only its structure. This is the dominant form of IC testing.

### Stuck-At Patterns

Target the single stuck-at fault model (SA0/SA1). Each pattern:
1. Loads specific values into all scan chains (shift-in)
2. Applies one capture clock pulse (SE deasserted)
3. Captures the combinational logic response into scan flip-flops
4. Shifts out the response (while shifting in the next pattern)

Characteristics:
- No at-speed requirement -- capture can occur at any frequency
- Typically the highest fault coverage achievable (97-99%+)
- Relatively compact pattern sets due to good dynamic compaction
- Detects a broad range of physical defects despite the simple fault model

### Transition Fault Patterns

Target slow-to-rise (STR) and slow-to-fall (STF) timing faults. Each pattern requires two capture cycles:

**Launch-Off-Shift (LOS)**:
1. Shift in the pattern (last shift cycle establishes the launch value)
2. One at-speed capture clock pulse (transitions and captures response)

Advantage: Simpler OCC design; fewer constraints.
Disadvantage: Limited initialization -- the last shift state determines the launch value, which constrains what transitions can be activated.

**Launch-Off-Capture (LOC)**:
1. Shift in the pattern
2. First at-speed capture pulse (launches the transition)
3. Second at-speed capture pulse (captures the response)

Advantage: More flexible initialization; higher transition fault coverage.
Disadvantage: Requires two at-speed pulses from OCC; some faults may require specific intermediate states.

Transition patterns require the OCC to generate at-speed clock pulses (at functional frequency) for the capture phase while using a slower clock for shift. Typical transition coverage targets are 93-98%.

### Path Delay Patterns

Target cumulative delay along specific signal paths. Pattern pairs create a transition at the path input and sensitize the entire path (non-controlling values on all side inputs). The response is captured after the at-speed delay.

Path delay patterns are usually generated for a selected subset of timing-critical paths rather than exhaustively for all paths. Selection is guided by STA results -- paths with low slack or paths through areas with known process sensitivity.

### Cell-Aware Patterns

Generated from cell-internal fault models derived from transistor-level defect simulation. A cell-aware library characterizes each standard cell for internal defects (transistor shorts, opens, bridging faults) and produces a fault model that ATPG uses alongside traditional models.

Cell-aware patterns are applied after stuck-at and transition patterns. They typically add 5-15% more patterns but can detect 2-5% additional defects, particularly intra-cell shorts that appear as neither stuck-at nor transition faults from the gate-level perspective.

## At-Speed Test Patterns

At-speed patterns verify that the circuit operates correctly at its target frequency. This encompasses transition fault patterns and path delay patterns but also includes specialized patterns:

**At-speed scan patterns**: Standard transition patterns applied with at-speed capture pulses.

**At-speed BIST patterns**: LBIST with at-speed capture, testing the design under realistic switching conditions with pseudo-random stimuli.

**Speed binning patterns**: Special pattern sets designed to characterize maximum operating frequency. Patterns target the most timing-critical paths and are applied at progressively higher frequencies to determine the speed grade.

## Low-Power Test Patterns

Power during test can be 2-5x higher than functional power due to the uncorrelated nature of ATPG patterns (50% toggle rate vs. 10-20% functional toggle rate). Excessive test power causes:
- IR drop that invalidates timing
- Thermal damage
- False failures (good parts failing due to power-induced timing violations)
- Reliability degradation

### Shift Power Reduction

During scan shift, all flip-flops toggle at the shift frequency. Techniques:
- **Low-power shift**: ATPG tools fill don't-care bits to minimize transitions during shift (adjacent scan cell values are set equal where possible)
- **Shift frequency reduction**: Lower shift clock frequency reduces dynamic power
- **Clock gating during shift**: Gate clocks to unused logic cones during shift

### Capture Power Reduction

The capture cycle creates a burst of switching activity. Techniques:
- **Capture power-aware ATPG**: Tools constrain patterns to limit the number of flip-flops that toggle during capture
- **Toggle budget**: Specify maximum allowed toggles per capture cycle (e.g., 20% toggle rate)
- **Multi-capture avoidance**: Some tools avoid patterns that cause ripple effects through multiple logic levels during capture
- **Power-aware pattern ordering**: Order patterns to minimize switching between consecutive captures

### Scan Chain Segmentation

Divide scan chains into segments that can be independently clocked, allowing partial-chain shift that reduces power.

## Scan Compression Patterns

Compression patterns are generated in the compressed domain -- the ATPG tool accounts for the decompressor and compressor structures when generating patterns.

Characteristics:
- External pattern data is much smaller than the equivalent uncompressed data
- The ATPG tool solves for values at the external channel inputs/outputs
- Don't-care exploitation is critical -- compression requires high X-density to achieve target ratios
- Patterns are stored on ATE in compressed format and decompressed on-chip during application

Pattern count with compression is often similar to uncompressed (same faults need detection), but the data volume per pattern is dramatically reduced.

## Functional Test Patterns

Functional patterns exercise the design through its intended operating modes. Unlike structural patterns, they are applied through primary inputs and observed at primary outputs without scan mode.

Uses for functional patterns:
- Validate analog/mixed-signal interfaces that scan cannot test
- Test timing-critical paths at actual operating conditions
- Verify power sequencing and mode transitions
- Supplement structural coverage for specific hard-to-test blocks
- Required for certain safety standards (ISO 26262)

Limitations: Much lower fault coverage than structural testing (typically 50-70%), much longer pattern sets, and difficult to generate automatically. Functional patterns are used selectively, not as the primary test vehicle.

## Pattern Reordering and Optimization

### Pattern Reordering

After ATPG generates patterns, they can be reordered to optimize various objectives:

**Coverage ramp optimization**: Place patterns with the highest incremental coverage first. If test is aborted early (time limit), maximum coverage is achieved with the applied patterns.

**Power optimization**: Order patterns to minimize the switching activity difference between consecutive patterns, reducing thermal stress.

**ATE memory optimization**: Group patterns with similar don't-care structures to improve ATE compression.

### Static Compaction

After pattern generation, merge compatible patterns to reduce total count. Two patterns are compatible if they have no conflicting specified values (one requires 0 and the other requires 1 at the same position). Static compaction can reduce pattern count by 10-30%.

### Dynamic Compaction

During pattern generation, the ATPG tool targets multiple faults with a single pattern. After detecting one fault, the tool adds constraints for additional faults that are compatible with the existing pattern. This is more effective than static compaction and is the default in modern tools.

## Pattern Formats and ATE Compatibility

### STIL (Standard Test Interface Language)

IEEE 1450 standard. Text-based format that describes signals, timing, scan chains, and pattern data.

```
Pattern "test_pattern_1" {
  V { scan_in = 0; scan_en = 1; clock = P; }
  // ... shift data ...
  V { scan_en = 0; clock = P; }  // capture
}
```

### WGL (Waveform Generation Language)

Another widely used text format, common with certain ATE vendors.

### Binary/Compressed Formats

Tool-specific binary formats for efficient storage and transfer. Often ATE-vendor-specific (e.g., Advantest, Teradyne formats).

### Pattern Translation

Patterns often need translation between formats or ATE platforms:
- Tessent provides pattern porting tools for format conversion
- TetraMAX can export in multiple formats
- Dedicated tools handle complex translations including timing remapping

## Pattern Validation

Before committing patterns to production, validation ensures correctness:

1. **Gate-level simulation**: Simulate patterns on the netlist to verify expected responses match ATPG predictions
2. **Timing-annotated simulation**: Verify at-speed patterns with SDF back-annotation
3. **Power analysis**: Simulate patterns with power analysis to verify power limits are not exceeded
4. **ATE dry-run**: Load patterns on ATE and verify they can be applied within timing and memory constraints
5. **Silicon correlation**: On first silicon, correlate ATPG coverage predictions with actual fail rates

## Pattern Set Management

Production test programs manage multiple pattern sets:

| Pattern Set | Fault Model | Speed | Typical Count | Purpose |
|-------------|------------|-------|---------------|---------|
| Stuck-at | SA0/SA1 | Slow | 5K-20K | Baseline coverage |
| Transition LOC | STR/STF | At-speed | 10K-40K | Timing defects |
| Cell-aware | Internal | Slow | 2K-10K | Intra-cell defects |
| IDDQ | Quiescent | DC | 100-500 | Current defects |
| BIST | Random | At-speed | 10K-1M cycles | Self-test |
| Functional | N/A | At-speed | Varies | Mode validation |

The total test program applies all pattern sets sequentially, with total test time typically 1-10 seconds per die depending on design complexity and compression effectiveness.
